# Security Policy

## Supported versions

The latest version on the `main` branch and the current GitHub Pages deployment are supported.

## Reporting a security concern

Do not place passwords, API keys, personal files, private messages or detailed exploit instructions in a public issue.

If GitHub's **Private vulnerability reporting** option is available on the repository's Security page, use it. Otherwise, open a minimal public issue stating that you found a possible security problem without including sensitive details, so the repository owner can arrange an appropriate follow-up.

## Defensive scope

GitHub Protector must not include real malware, credential-stealing behavior, persistence mechanisms or instructions for bypassing device protections. Test files must be harmless indicators such as EICAR where legally and safely appropriate, clearly labelled, and never executed by this project.
